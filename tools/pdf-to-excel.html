About this tool

This tool extracts text from your PDF and structures it for spreadsheet import. Three modes: Auto (recommended — picks the right strategy per document), plain text (each PDF line becomes one row with the full text in a single cell — best for articles, CJK content, letters, and any reading-oriented PDF), and column grouping (detects table columns from x-position alignment — best for actual data tables).

How it works

  • Upload a PDF — everything happens in your browser, no upload.
  • We extract text with positional information (x, y, width) using pdf.js.
  • In Auto mode we analyze the first page's x-position distribution: if the same x-positions appear as item-starts in ≥ 30 % of lines, we treat it as a table and use column grouping; otherwise we fall back to plain text. The chosen mode is shown in the result panel.
  • In plain text mode, each PDF line is one CSV row with all characters concatenated into one cell. Smart spacing: a real gap (e.g. between English words) becomes a space; CJK characters (no gap) stay joined. Blank rows are inserted at paragraph breaks.
  • In column-grouping mode, we only treat x-positions as columns if they appear as item-starts in ≥ 30 % of lines within a block. This filters out character-level jitter so a single phrase doesn't get split into phantom columns.
  • Output is UTF-8 with BOM so Excel detects CJK / emoji correctly when you double-click the .csv.

Limitations

  • Real table detection (with merged cells, borders) is best-effort. For complex tables, expect to clean up in Excel.
  • Scanned PDFs need OCR first to have extractable text.
  • For pixel-perfect tables, use PDF to Image + a paid OCR service.

Frequently asked questions

Which extraction mode should I pick?

Use Auto (the default) for most cases. It picks plain text for articles / CJK content and column grouping for real tables. If Auto picks wrong, switch to the other mode manually.

My Chinese / Japanese / Korean PDF came out with phantom columns — how do I fix it?

Switch to plain text mode. Column grouping assumes the PDF has aligned vertical columns; an article-style PDF will produce many phantom columns even when there's only one logical text flow. The new column-detection algorithm only treats x-positions as real columns if they appear as item-starts in ≥ 30 % of lines, which prevents most phantom-column cases — but plain text is still the safest bet for CJK articles.

CSV or TSV?

CSV (comma-separated) is the universal default. Choose TSV (tab-separated) if your data contains many commas — TSV avoids the need to escape them.

Can I convert directly to .xlsx?

Currently we output CSV/TSV, which Excel opens natively. A native .xlsx export is on the roadmap — for now, just rename .csv to .xlsx or open in Excel and save as .xlsx. Output is UTF-8 with BOM so Excel auto-detects encoding for CJK / emoji.
